# A Demo Visitor gets its own fictitious Customer and Attendant

The public demo has to show the human-in-the-loop Approval flow to an anonymous Demo Visitor without any real Attendant behind it. Each Demo Visitor therefore gets a fictitious Customer cloned from a template (Orders in different states) and a fictitious Attendant of its own, whose powers are limited to that Customer's Approval Requests (and a read-only view of that Customer's Tickets); decisions are recorded against that Attendant, so the Audit Log reads coherently. A shared seeded Customer was rejected because one visitor's Cancellation would spoil the next visitor's demo, and a global Attendant queue or a shared demo Attendant was rejected because visitors could see or decide each other's requests. Everything is discarded by the daily Demo Reset.
